# Release checklist

The checks that must pass before each release is tagged. Tick them in the release PR's description. The steps
themselves (version bump, tag, publish) are in [the release process](branching-and-releases.md#release-process).

## Product works as documented

- [ ] Clean **Windows + NVIDIA** machine: install exactly as the README says (both the portable bundle and from source),
      run `erasedub run` on a demo clip → correct video, no manual fixes.
- [ ] Windows from source: `erasedub doctor` says torch "is a CPU-only build but an NVIDIA GPU is present" with the
      CPU torch from the lock file, and is clean after the documented torch 2.8 / cu128 reinstall. Update the pinned
      versions in the docs if the locked WhisperX version changed. WhisperX also pins `torchcodec` on Windows
      (`>=0.6,<0.8` for 3.8.6); `--no-deps` leaves it untouched, so `pip check` must confirm it still fits the
      reinstalled torch.
- [ ] Clean **Linux + NVIDIA** machine: same, with uv (`uv sync`), pip and the Docker image (amd64). Ubuntu
      22.04 via the uv route.
- [ ] **Machine without a GPU** (e.g. macOS): `run` skips erasing, says so clearly (and suggests `lama`), and still
      produces a translated, voiced, subtitled video. With `erase.provider = "lama"` it erases on the CPU, and on
      Apple MPS if supported.
- [ ] **Each eraser** (`sttn`, `propainter`, `lama`) run on the demo set; if an eraser or its
      defaults changed, re-measure and update `docs/erasers.md`. ProPainter's licence notice shows in the plan, `plugins`, `doctor` and the
      web UI.
- [ ] `--gpu modal` tested with a fresh Modal account.
- [ ] **Targets vi / en / zh**: listen to the voice and check the subtitles of each rendered demo.
- [ ] Every command in README.md, README.zh-CN.md, README.vi.md and docs/ has been run as written.

## Safety and licensing

- [ ] No keys, tokens, `.env` files, signed URLs or personal emails anywhere in the history
      (`gitleaks detect` on the full history, not only the working tree).
- [ ] No keys in downloaded models or build artefacts.
- [ ] `uv sync --extra full` pulls nothing unexpected: review the resolved dependency tree for typosquats.
- [ ] Models download only from the locations their authors publish or point to; eraser files at pinned revisions.
- [ ] Non-commercial components (ProPainter, WhisperX alignment models such as the Vietnamese and VoxPopuli ones)
      are strictly opt-in (alignment off by default; ProPainter only via its extra and `erase.provider`), never
      vendored into the wheel, the Docker image or the Windows bundle, and
      [models-and-licenses.md](../models-and-licenses.md) is current.
- [ ] **STTN weights:** until their licence and provenance are resolved (they are published on Google Drive with
      no separate licence), they are not pre-fetched into the Docker image or the Windows bundle.
- [ ] Docker image and Windows bundle ship the GPL ffmpeg licence texts, the exact upstream FFmpeg revision and the
      BtbN build-script commit.
- [ ] **GPL corresponding source:** every release that ships the Docker image or the Windows bundle also publishes
      the full corresponding FFmpeg source — a mirrored source tarball as a release asset (FFmpeg plus the GPL/LGPL
      libraries in that build, e.g. x264), kept available as long as the binaries are. BtbN autobuilds expire, so a
      link to them is not enough. The exact FFmpeg and BtbN build-script commits are recorded in the `SOURCE.txt`
      that the build writes (`/usr/share/doc/ffmpeg/SOURCE.txt` in the image, `ffmpeg\SOURCE.txt` in the bundle;
      generated by the `Dockerfile` and `packaging/windows/build.ps1`). See
      [ADR 0010](../adr/0010-gpl-ffmpeg-in-binary-distributions.md).
- [ ] edge-tts (LGPL-3.0) stays a replaceable package in the Docker image and bundle, with its licence text.
- [ ] **Bump the Debian base-image pin** (`PYTHON_IMAGE` digest in the `Dockerfile`) when it is due, and re-check
      the ffmpeg and uv image pins at the same time.
- [ ] Demo media matches [demo-assets.md](../demo-assets.md): release asset names, README animations (animated WebP): previews under 500 KB, full comparisons at most 3 MB.

## README and docs

- [ ] Re-check the comparison table against the other projects' current READMEs; update star counts with
      `gh api repos/<owner>/<repo> --jq .stargazers_count` and the date.
- [ ] Add badges only for things that exist (CI, licence) — no placeholder badges.
- [ ] All relative links resolve; README.md uses absolute GitHub URLs. The `links (offline)` check is green, and
      a manual run of `links (external)` (Actions → Links → Run workflow) is green or its failures are understood.
- [ ] **First release only:** after the tag has pushed the image to GHCR, delete the `ghcr.io/sting11k/erasedub` exclusion
      from `lychee.toml`, then run `links (external)` again.
- [ ] `uv run pre-commit run --all-files` is clean.

Then follow [the release process](branching-and-releases.md#release-process). After publication, add the demo
assets and the hardware/language notes to the release body (step 6).
